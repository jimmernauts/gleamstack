## Summary

**Snapshot: 2026-08-22.** IndexedDB is the conservative storage choice for Mealstack: it is a mature, asynchronous, same-origin transactional API, supported in Safari/iOS and desktop browsers (MDN, updated 2025-04-03; compatibility cross-check Can I Use, accessed 2026-08-22). OPFS is also supported by WebKit from macOS 12.2/iOS 15.2, but is unavailable in Safari Private Browsing and its synchronous access path is worker-only (WebKit, 2021-12-14; MDN, 2025-07-14).

Neither API guarantees permanence. Both are origin storage subject to quota, user clearing, storage pressure, and Safari’s proactive inactivity policy. Installed standalone/full-screen Home Screen apps receive browser-sized WebKit quota, but the evidence about exemption from the seven-day script-writable-data deletion is version-dependent: an older WebKit engineer said standalone/fullscreen `Web.app` avoids the Safari behavior, while current WebKit policy still describes seven-day inactivity eviction without explicitly documenting a universal standalone exemption. Treat retention as best effort and test target OS releases.

## Key Findings

- **Quota/eviction:** WebKit 17+ gives browser apps up to ~60% of disk per origin and ~80% overall; standalone Home Screen apps get the same quota. Quota is an upper bound, not a promise; writes can throw `QuotaExceededError`. Best-effort data is LRU-evictable under pressure/overall limits; Safari may proactively delete script-created data after seven days without user interaction (WebKit, 2023-06-20; MDN, updated 2026-01-05).
- **Persistence:** `estimate()`, `persisted()`, and `persist()` are supported in WebKit 17+/iOS 17+. `persist()` returns a Boolean; Safari/Chromium generally auto-approve/deny heuristically, with no dependable user prompt. WebKit says Home Screen status is one heuristic. A successful persistent mode excludes the origin from ordinary eviction, but not explicit user deletion, uninstall, corruption, or all platform failure modes. Never rely on approval (WebKit 2023-09-18; MDN 2024-07-26; Storage Standard, accessed 2026-08-22).
- **Seven-day exception:** WebKit bug 232302 (2021) records “no exception in Safari,” but says `standalone` or `fullscreen` opens in `Web.app` and gets the desired behavior. This is implementation evidence, not a standards guarantee; current storage-policy prose does not clearly restate the exemption. A plain Safari tab, `minimal-ui`, and EU alternative-engine/browser configurations must be treated separately and verified.
- **Service workers:** They are event-driven, can be terminated whenever idle, and do not retain in-memory state across restarts. `event.waitUntil()` only keeps the worker alive until that event’s promise settles. Cache/offline fetch works while registration and storage remain, but background execution timing is not guaranteed (MDN, 2025-05-30; W3C Service Workers, accessed 2026-08-22).
- **Background sync:** One-shot Background Sync and Periodic Background Sync are not supported in Safari/iOS as of the 2026-08-22 Can I Use tables. Do not make them part of Mealstack’s correctness path; use foreground retry, `online`, `visibilitychange`/`pageshow`, app startup, and explicit “sync now.”
- **Private browsing:** Private sessions can have different quotas and are normally deleted at session end. OPFS is explicitly unavailable in Safari Private Browsing; IndexedDB behavior/Blob support has varied by Safari version. Detect failures and clearly label private mode as non-persistent.
- **Cross-tab:** IndexedDB coordinates transactions, but schema upgrades can be blocked by open connections; handle `versionchange` by closing and notify other tabs. OPFS sync access handles are exclusive and worker-only, so SQLite-Wasm needs a single-worker ownership/lock protocol. Web Locks or a BroadcastChannel can coordinate tabs.
- **Dexie/IndexedDB vs SQLite-Wasm/OPFS:** For a small flat recipe dataset, Dexie adds ergonomic queries/migrations while retaining broad Safari compatibility and simpler multi-tab behavior. SQLite-Wasm adds relational SQL, portability of a database file, and high-throughput/in-place writes, but adds Wasm/worker startup, exclusive-file coordination, OPFS/private-mode compatibility risk, and potentially COOP/COEP requirements for the Chrome SQLite build. It does not improve durability: OPFS has the same quota/eviction class as IndexedDB.

**Product requirements and POC tests:** ship IndexedDB/Dexie as the baseline; treat sync as a foreground state machine with idempotent outbox records and retry on launch, visibility return, `online`, and manual action; call `persist()` and display only its actual result; export/import recipes for recovery; detect private mode and OPFS/IDB write failures. POC on iOS/iPadOS Safari and installed `standalone`/`fullscreen`, macOS Safari, Chrome, and Firefox: write/read recipes; close/reopen; two-tab concurrent edits and upgrade; offline edit then reconnect; kill/relaunch; private mode; `estimate()`/`persisted()`/`persist()`; quota-pressure simulation; and a seven-day inactivity test with both Safari tab and Home Screen app. Separately benchmark Dexie versus SQLite-Wasm/OPFS and test two tabs plus worker termination.
