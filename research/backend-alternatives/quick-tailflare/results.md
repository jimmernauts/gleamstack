## Summary

**Tailflare is not currently a complete private-app gate.** It embeds a Tailscale node as WASM in a Cloudflare Durable Object (DO), then uses a tailnet-reachable MagicDNS endpoint to mint a short-lived JWT. The public Worker callback verifies that JWT and sets an `HttpOnly` cookie. However, the repository’s Worker does not apply that cookie check globally: only the `me` RPC validates it; static assets, `/api/v1/proxy`, and the Tailscale RPC procedures remain reachable without it ([README](https://github.com/simplyzetax/tailflare/blob/master/README.md), [index.ts](https://github.com/simplyzetax/tailflare/blob/master/apps/worker/src/index.ts), [me.ts](https://github.com/simplyzetax/tailflare/blob/master/apps/worker/src/orpc/procedures/me.ts)).

For Gleamstack, use **Cloudflare Workers Access** if the priority is securing the existing `workers.dev` deployment with minimal custom code. Use Tailflare only if proving tailnet membership is specifically required and you accept integrating and maintaining the missing authorization middleware. Tailflare does not make the Cloudflare endpoint network-private; it is an Internet-reachable endpoint whose application authorization can be based on a tailnet proof.

## Key Findings

- **Flow/trust boundaries:** `/api/v1/notouchlogin` redirects the DO to Tailscale login when needed, otherwise serves browser JavaScript that fetches `http://<Tailflare-MagicDNS>/api/v1/notouchlogin`. The DO maps the request source IP to a known Tailscale peer and signs a three-hour HS256 JWT; the public callback verifies it with `AUTH_SECRET` and sets `tailflare_token` ([index.ts](https://github.com/simplyzetax/tailflare/blob/master/apps/worker/src/index.ts), [tailscale.ts](https://github.com/simplyzetax/tailflare/blob/master/apps/worker/src/durable-objects/tailscale.ts)). The callback is necessarily public and carries the JWT in a URL query parameter. This is tailnet-proof authentication, not tailnet-only transport.
- **Deployment:** It works directly on `*.workers.dev`; the repository demonstrates that URL, and Cloudflare says workers.dev needs no custom domain ([README](https://github.com/simplyzetax/tailflare/blob/master/README.md), [workers.dev](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/)). Tailflare requires a Workers Paid plan for DOs, a Tailscale account/reusable auth key, WASM build tooling, a DO migration, and an `AUTH_SECRET` of at least 32 bytes ([README](https://github.com/simplyzetax/tailflare/blob/master/README.md), [wrangler.jsonc](https://github.com/simplyzetax/tailflare/blob/master/apps/worker/wrangler.jsonc), [.env.example](https://github.com/simplyzetax/tailflare/blob/master/.env.example)).
- **Assets and `/api/db-config`:** Current config runs the Worker first only for `/api/*`, `/rpc/*`, and `/scalar`; matching static assets bypass it ([wrangler.jsonc](https://github.com/simplyzetax/tailflare/blob/master/apps/worker/wrangler.jsonc)). Cloudflare documents that asset-first is the default and that `assets.run_worker_first` is required for authentication middleware ([Worker script](https://developers.cloudflare.com/workers/static-assets/routing/worker-script/)). Thus Tailflare cannot protect Gleamstack’s static assets as-is. `/api/db-config` would reach the Worker first but currently has no Tailflare route and would 404; it must be merged into the Worker and explicitly authorized. No service binding or reverse proxy is required in the same Worker; an assets binding plus `ASSETS.fetch()` is needed if the Worker handles assets itself. Exempt the login and callback routes from the gate.
- **Maturity (repository facts):** Latest commit is `46c138f` (2026-04-28), implementing no-touch-login redirection; the preceding commit vendors a large Tailscale update. The repo has 4 stars, 0 open issues, no releases, is MIT and unarchived ([metadata](https://api.github.com/repos/simplyzetax/tailflare), [commits](https://api.github.com/repos/simplyzetax/tailflare/commits?per_page=5), [releases](https://github.com/simplyzetax/tailflare/releases)). Dependencies include vendored Go/Tailscale WASM, Bun/Turbo, Wrangler, Hono, oRPC, jose, and zod ([package.json](https://github.com/simplyzetax/tailflare/blob/master/package.json), [worker package](https://github.com/simplyzetax/tailflare/blob/master/apps/worker/package.json)). The README lists DO pricing, one node per DO, and no WebSockets; the code calls DO initialization experimental ([README](https://github.com/simplyzetax/tailflare/blob/master/README.md)). Recommendation: treat it as early-stage infrastructure, not a drop-in security product.
- **Comparison:** Access protects the Worker before execution, including its `workers.dev` hostname, requires no custom domain or app auth code, exposes identity via `ctx.access`, and is free for teams under 50 users ([Access for Workers](https://developers.cloudflare.com/workers/configuration/cloudflare-access/), [Access pricing](https://www.cloudflare.com/sase/products/access/)). Worker Basic Auth is simpler and keeps the deployment, but requires hand-written middleware/secret handling; Cloudflare labels its sample unsuitable for production and warns credentials require HTTPS ([Basic Auth](https://developers.cloudflare.com/workers/examples/basic-auth/)). Tailscale Serve is genuinely tailnet-only and uses MagicDNS/automatic HTTPS, but requires moving the app to a Tailscale node rather than retaining the Worker ([Serve](https://tailscale.com/docs/features/tailscale-serve)).
- **Turso conclusion unchanged:** Turso database access uses bearer tokens in `Authorization` and supports scope/expiry ([Turso HTTP reference](https://docs.turso.tech/sdk/http/reference), [token creation](https://docs.turso.tech/api-reference/databases/create-token)). Any authorized browser performing direct sync can inspect the token. Deliver it at runtime rather than embedding it in static JavaScript, but regard runtime delivery as concealment from unauthenticated users—not secrecy from the authorized browser; server-side proxying is required for a true secret.
