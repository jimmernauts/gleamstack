## Summary

Checked first-party material available on **2026-08-22**. Plain Dexie is an Apache-2.0 browser-storage library, not a sync product: it gives Mealstack the least lock-in but makes the entire replication system an application/backend responsibility. Dexie Cloud adds a server-authoritative sync protocol, auth, permissions, and export/migration, but introduces a hosted commercial dependency (or a separately licensed on-prem server). Triplit is a full-stack TypeScript system whose repository is AGPL-3.0; its client is genuinely local-first, but current hosted pricing/limits, restore semantics, and detailed delete/conflict guarantees were not verifiable in first-party docs.

For a flat, small Gleam-to-JS PWA, plain Dexie is attractive if Mealstack can accept custom sync work; Dexie Cloud is the shortest path to multi-device sync; Triplit is viable if TypeScript/server deployment and AGPL review are acceptable. These are trade-offs, not a ranking.

## Key Findings

### (A) Plain Dexie.js + custom backend

- **License/boundary:** Dexie.js and its repository addons are Apache-2.0; no Dexie usage fee or commercial-use boundary is stated ([LICENSE](https://github.com/dexie/Dexie.js/blob/master/LICENSE), [repo](https://github.com/dexie/Dexie.js/)). Current maintenance signal is strong: Dexie 4.4.4 was published 2026-06-16 and the repo shows a 2026-07-08 push ([release](https://github.com/dexie/Dexie.js/releases/tag/v4.4.4)).
- **Local/offline:** Dexie wraps browser IndexedDB, so records persist locally and reads/writes work offline ([README](https://github.com/dexie/Dexie.js/)). A client can retain the full selected dataset simply by storing all selected records; there is no automatic query-subset sync policy.
- **Atomic outbox:** IndexedDB transactions span multiple object stores. `db.transaction('rw', db.items, db.outbox, () => { ... })` can atomically mutate a record and append its outbox entry; commit failure rolls back both ([transaction docs](https://dexie.org/docs/Dexie/Dexie.transaction())). The custom layer still owns change capture, IDs, push/pull cursors, retries/idempotency, auth, server authority, conflict/merge rules, deletes/tombstones/GC, filtering, and backup/restore. Legacy `dexie-syncable`/`dexie-observable` are explicitly unmaintained ([README](https://github.com/dexie/Dexie.js/)).
- **Pros/deal-breaker:** portable, tiny, Gleam-JS-friendly; deal-breaker is substantial sync engineering and operational ownership. Self-host/Cloudflare are properties of the backend, not Dexie.

### (B) Dexie Cloud

- **License/commercial:** the client/addon is in the Apache-2.0 Dexie repo, while the server is a separately licensed on-prem product with source/private-repo access ([on-prem docs](https://dexie.org/docs/cloud/premium-software)). Current hosted pricing lists free evaluation/demo users, **3 production seats**, **100 MB** storage, and rate limits of **50 sync requests/5 minutes/user** (eval) or **200/5 minutes/user** (production); production seats beyond the free allowance are paid ([pricing](https://dexie.org/pricing), [limits](https://dexie.org/docs/cloud/limits)).
- **Behavior/authority:** IndexedDB is the offline cache; sync can restore the server’s canonical snapshot for the user’s permitted subset, not necessarily the entire database. The server is authoritative by default; transactions are atomic server-side; declarative `modify`/`delete` where-clauses are replayed consistently; `update` merges different properties, while same-property conflicts are last-operation-wins. Y.js supplies CRDT behavior for collaborative documents ([consistency](https://dexie.org/docs/cloud/consistency)).
- **Auth/export/deployment:** default email OTP, OAuth (Google/GitHub/Microsoft/Apple/custom), or custom auth; long-lived non-exportable IndexedDB key ([authentication](https://dexie.org/docs/cloud/authentication)). CLI export/import supports full zip data, schema, roles, members, blobs, and Y.js; import is additive unless values are null ([CLI](https://dexie.org/docs/cloud/cli)). Hosted or on-prem Node/Postgres is documented; Cloudflare Workers is not ([on-prem docs](https://dexie.org/docs/cloud/premium-software)). Migration/replication to on-prem reduces lock-in, but hosted continuity/SLA remains a vendor concern.

### (C) Triplit

- **License/commercial:** official repo is **GNU AGPL-3.0** ([LICENSE](https://github.com/aspen-cloud/triplit/blob/main/LICENSE)); the repo’s “fully open-source” marketing is not a separate commercial grant ([README](https://github.com/aspen-cloud/triplit/)). AGPL section 13 requires a modified network server to offer corresponding source to remote users; applicability to Mealstack’s combined/distributed app requires legal review, not an automatic conclusion. Hosted pricing/limits were not published in verifiable fetched first-party content.
- **Behavior/authority:** the client uses IndexedDB-backed local storage, optimistic writes, an outbox/double buffer, WebSockets, automatic reconnect, and query-based incremental sync ([client](https://github.com/aspen-cloud/triplit/blob/main/packages/client/README.md), [sync engine](https://raw.githubusercontent.com/aspen-cloud/triplit/main/packages/client/src/sync-engine.ts)). Thus it can retain a complete selected dataset only if Mealstack subscribes/fetches queries covering it; no blanket full-dataset guarantee was found. Server permissions and acknowledgements are authoritative. README claims property-level conflict resolution/CRDTs, but detailed documented delete-vs-update policy and tombstone retention/GC were not found; source exposes delete changes and rollback, not a documented tombstone contract.
- **Self-host/auth/export/continuity:** self-hosting and a Hono/Cloudflare Workers server are documented; Workers memory constraints are noted ([Cloudflare guide](https://www.triplit.dev/blog/release-notes-2024-11-22)). Clients use tokens/session APIs; auth-provider choice is not a Dexie-Cloud-style zero-config promise. A server `POST /db-download` full export is documented, but restore/import is unresolved ([release note](https://www.triplit.dev/blog/release-notes-2024-12-06)). Releases show active packages through **31 July** (client 1.0.50; server 1.1.8; CF worker 0.0.25) ([releases](https://github.com/aspen-cloud/triplit/releases)); hosted continuity, SLA, current price, and limits remain unresolved.
